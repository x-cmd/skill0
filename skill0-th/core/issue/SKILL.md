# issue

เป็นส่วนหนึ่งของ [devloop](../devloop/SKILL.md)

## เทมเพลต issue พัฒนาใหม่

```
gh issue create --title "<ขอบเขต>: <คำอธิบายสั้น>" --body "$(cat <<'EOF'
## เป้าหมาย
<วัตถุประสงค์หนึ่งบรรทัด>

## ผลลัพธ์หลัก
- [ ] KR-1: <ผลลัพธ์ที่ตรวจสอบได้>
- [ ] KR-2: <ผลลัพธ์ที่ตรวจสอบได้>

## rule.yml
```yaml
goal: "<เหมือนข้างบน>"
keyresults:
  - kr-1: "<เหมือนข้างบน>"
  - kr-2: "<เหมือนข้างบน>"
rules:
  - id: <rule-id>
    name: <name>
    apply: "<รูปแบบไฟล์>"
    level: error
    desc:
    - <เกณฑ์>
```

## ภาพหน้าจอ
- ก่อน: <รูปภาพ หรือ "ไม่มี">
- หลัง: <รูปภาพ หรือ "รอดำเนินการ">
EOF
)"
```

## วงจรชีวิตของ issue

| ขั้นตอน | การดำเนินการ | เนื้อหาคอมเมนต์ |
|-------|--------|-----------------|
| สร้างแล้ว | `gh issue create` พร้อมเทมเพลต | เป้าหมาย ผลลัพธ์หลัก rule.yml |
| กำลังทำ | อัปเดตตามความคืบหน้าของงาน | บันทึกความคืบหน้า ภาพหน้าจอระหว่างทำ |
| ตรวจสอบแล้ว | `x rule check` ผ่าน | ผลการตรวจสอบ rule ภาพหลัง |
| ปิดแล้ว | `gh issue close` | commit SHA สรุปผลการตรวจสอบครั้งสุดท้าย |

## เทมเพลตคอมเมนต์เมื่อเสร็จสิ้น

```
gh issue comment <n> --body "$(cat <<'EOF'
## ตรวจสอบแล้ว
- rule.yml: <บล็อกโค้ดหรือลิงก์>
- x rule check: ผ่าน
- ก่อน: <รูปภาพ>
- หลัง: <รูปภาพ>
- Commit: <sha>
EOF
)"
```

## กฎ

- **ต้อง** มี `goal` และ `keyresults` ในทุก issue ที่พัฒนา — ไม่มีข้อยกเว้น
- **ต้อง** โพสต์ rule.yml เป็นบล็อกโค้ดในเนื้อหา issue หรือคอมเมนต์แรก
- **ต้อง** จับภาพหน้าจอก่อนและหลังสำหรับการเปลี่ยนแปลงส่วนหน้าเว็บ
- **ห้าม** ปิด issue โดยไม่มีหลักฐานการตรวจสอบ
- ผูก issue เข้ากับ project board เพื่อให้เห็นความคืบหน้าตาม roadmap

## ที่เกี่ยวข้อง

- [devloop](../devloop/SKILL.md) — ตัวติดตามสำหรับวงจรที่ขับเคลื่อนด้วยเป้าหมาย (เป้าหมาย/rule.yml/KR)
- [repo](../repo/SKILL.md) — issue ผูกกับ repo ในโครงสร้าง x-repo
