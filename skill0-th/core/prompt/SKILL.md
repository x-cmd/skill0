# Prompt

## หลักการหลัก: ใช้ซ้ำ อย่าทำซ้ำ

Prompt ใน x-cmd ประกอบขึ้นจากชิ้นส่วนที่ใช้ซ้ำได้ ไม่ได้เขียนเป็นก้อนเดียว เทมเพลต prompt จะมีตัวแปร `<PLACEHOLDER>` ที่ shell module แก้ค่าให้ในเวลารัน

ตัวอย่างจาก `claw`:
```
first_contact.md          # ใช้เดี่ยว ๆ — โหลดเข้า <FIRST_CONTACT_PROMPT>
msg_telegram.md           # ประกอบ: <FIRST_CONTACT_PROMPT> + <CHECK_PROMPT> + <MSG>
msg_feishu.md             # ชิ้นส่วนเดียวกัน แต่ใช้ adapter คนละแพลตฟอร์ม
heartbeat.md              # เวิร์กโฟลว์ต่างกัน แต่ใช้ร่วมกัน <CHECK_PROMPT>
```

**เหตุผล**: การแก้ครั้งเดียวกระจายไปทุกที่ adapter ของแต่ละแพลตฟอร์ม (Telegram, Feishu, WeChat) ใช้กฎด้านพฤติกรรมร่วมกัน แต่ต่างกันที่คำสั่งส่งและข้อจำกัดการจัดรูปแบบ

ดูรูปแบบการใช้ซ้ำอย่างละเอียดได้ที่ [reusing.md](reusing.md)

## กฎโครงสร้าง

- ไฟล์ prompt แต่ละไฟล์คือชุดคำสั่งที่สมบูรณ์และพึ่งตัวเอง สำหรับสถานการณ์หนึ่ง ๆ
- ใช้ตัวแปรรูปแบบ `<UPPER_CASE>` — ห้ามฝังข้อมูลจริงลงไป
- ตัวแปรถูกแก้ค่าโดยโมดูลที่เรียก ไม่ใช่โดย prompt เอง
- ชิ้นส่วน = ฟังก์ชัน (ตรรกะและลำดับขั้น) ส่วนข้อมูลถูกเติมตอนรัน (เหมือนการตั้งค่าอาร์กิวเมนต์)

## รูปแบบการบังคับใช้ความปลอดภัย

กฎด้านความปลอดภัยและพฤติกรรม **ต้อง** เขียนให้ชัดเจนและหนักแน่น:

```
=== กฎที่ห้ามละเมิด ===
>> กฎ 1: stdout ของคุณมองไม่เห็น ทุกคำตอบต้องใช้คำสั่งส่ง <<
>> กฎ 2: ตอบก่อน คิดทีหลัง งานที่ไม่ง่าย ให้ส่ง ack ทันที <<
>> กฎ 3: งานซับซ้อน/ยาว → ใช้ `x agent run` ห้ามบล็อกผู้ใช้ <<
```

ใช้ MUST, NEVER, DO NOT ดูกฎด้านภาษาความปลอดภัยที่ [skill0-writer](../skill0-writer/SKILL.md)

## รูปแบบคู่มือการจัดรูปแบบ

เมื่อ prompt ต้องรองรับหลายแพลตฟอร์มที่ความสามารถในการจัดรูปแบบต่างกัน:

```
คู่มือการจัดรูปแบบ:
- WeChat / WeCom: จัดรูปแบบได้จำกัด ข้อความธรรมดา ลิสต์ emoji ไม่มีตาราง
- Telegram: markdown เต็มรูปแบบรวมตาราง ไม่เกิน 4096 ตัวอักษร
- Feishu: markdown เต็มรูปแบบ ข้อความการ์ดต้องใช้ JSON
```

## ตัวอย่างจริง

ปัจจุบันชิ้นส่วน prompt อยู่ใน `lib/data/prompt/` ของแต่ละโมดูล (เช่น `claw/lib/data/prompt/`)
จะย้ายไปที่ `skill0/lib/skill0/<subskill>/` ในอนาคต — โครงสร้างเหมือนเดิม เป็นตำแหน่งมาตรฐาน

ตัวอย่างปัจจุบันใน `claw/lib/data/prompt/`:
- `first_contact.md` — คำทักต้อน workspace ใหม่ เป็นชิ้นส่วนที่ใช้ซ้ำได้
- `heartbeat.md` — agent เบื้องหลัง อ่านสถานะของ workspace
- `msg_<แพลตฟอร์ม>.md` — ตัวจัดการข้อความแยกตามแพลตฟอร์ม ใช้ชิ้นส่วนร่วมกัน
