# Score
"อย่าเดา ให้นับ"
กรอบการให้คะแนนแบบถ่วงน้ำหนักตามมิติสำหรับ AI agent
## วิธีใช้
**เข้าใจก่อน ให้คะแนนทีหลัง** ถามให้พอก่อนที่จะกำหนดมิติ มิติผิด → คะแนนผิด ไม่ว่าจะละเอียดแค่ไหนก็ตาม
**ร่างแล้วปรับทีหลัง** เมื่อความต้องการยังไม่ชัดเจน ให้ทำมาตรฐานที่ดีที่สุดเท่าที่ทำได้ ให้คะแนน แล้วแสดงผล ผู้ใช้จะตอบสนองต่อการจัดอันดับที่เห็นภาพ — "ปัจจัยนี้ควรสูงกว่านี้" "คุณพลาด X" นั่นคือสัญญาณ ปรับแล้วให้คะแนนใหม่ การปรับหนึ่งรอบดีกว่าการเดาสิบรอบ
**agent คือผู้วิเคราะห์** หลังคำนวณ ให้อ่าน TSV อธิบายว่าทำไม X ชนะ Y ชี้ให้เห็นสิ่งที่น่าแปลกใจ เสนอการปรับปรุง การจัดอันดับเป็นจุดเริ่มต้นของบทสนทนา ไม่ใช่จุดจบ
## ขั้นตอนหลัก
```
① เข้าใจความต้องการ  → ② กำหนด score.yml  → ③ ให้คะแนน score.tsv  → ④ x score compute  → ⑤ รายงานและปรับปรุง
```
ผลลัพธ์: `target, total, rank, block, reason, <dim> (X%), evidence` ค่ารวม 0–100 เรียงจากมากไปน้อย rank=1 คือดีที่สุด
## ตัวอย่าง — ช่วยผู้ใช้ตัดสินใจเรื่องสโลแกนโฆษณา
1. คุยกับผู้ใช้เพื่อกำหนดมิติการประเมินและเกณฑ์ เขียน `slogan.score.yml`
2. AI ให้คะแนนแต่ละสโลแกนตามมิติ (0–10 พร้อมหลักฐาน) → `slogan.score.tsv` เว้นค่ารวมและอันดับว่างไว้
3. `x score compute slogan.score.yml slogan.score.tsv` → เติมค่ารวม + อันดับ
4. อ่านผลลัพธ์ คุยกับผู้ใช้ ปรับคะแนนหรือเพิ่มตัวเลือก แล้วทำซ้ำ
5. หรือ: `x score iter -f slogan.score.yml slogan.score.tsv "<ข้อเสนอแนะ>"`
ตัวอย่างเพิ่มเติม: [EXAMPLE.md](EXAMPLE.md)
## โมเดลสองไฟล์
- `*.score.yml` — มาตรฐานที่ใช้ซ้ำได้: มิติ ปัจจัย คำอธิบาย
- `**.score.tsv` — เป้าหมาย + คะแนน + หลักฐาน คอลัมน์ที่ 1 = ชื่อเป้าหมาย
`x score compute <yml> <tsv>` เหมือนกับ `python compute.py`
## สถานการณ์การใช้งาน
1. **ให้ agent มีเวิร์กโฟลว์การตัดสินใจ** score.yml ยึด agent ไว้กับกระบวนการที่มีโครงสร้าง — agent ทำตามมาตรฐาน ไม่ใช่ตามอารมณ์ของข้อความล่าสุด
2. **การตัดสินใจอิงกฎ** มิติ × ปัจจัย × หลักฐาน → ค่ารวมถ่วงน้ำหนัก → อันดับ ทุกคะแนนยึดกับข้อเท็จจริง เหตุผลโปร่งใส
3. **ปรับตามความต้องการที่ต่างกัน** สลับมิติ ปรับปัจจัย เพิ่มตัวกรองแบบบังคับ (คอลัมน์ `block`) เทมเพลตเดิม ใช้กับคนละกลุ่มได้
4. **วิวัฒนาตามที่ความต้องการชัดขึ้น** ร่าง → ให้คะแนน → รับ feedback → ปรับ → คมขึ้น
5. **มาตรฐานเป็นไฟล์ + เก็บผลลัพธ์ไว้สำหรับทุกสกิล** score.yml = มาตรฐานการตัดสินใจ score.tsv = บันทึกการตัดสินใจ เก็บถาวร ตรวจสอบ แชร์ได้

## สูตร
```
total = Σ(ปัจจัย × คะแนน) ÷ Σ(ปัจจัย) × 10   →   0–100
```
- **ปัจจัย (factor)** — จำนวนเต็ม 1–10 ค่าฐาน = 2 1=น้อย 4=2× 6=3× 8=4× 10=5× ปรับเป็นสเกลร่วมอัตโนมัติ
- **คะแนน (score)** — 0–10 ต่อมิติ ยึดหลักฐาน
- **total** — ค่ารวมถ่วงน้ำหนัก 0–100
หัวตารางของแต่ละมิติจะแสดงน้ำหนักเป็นเปอร์เซ็นต์: `ปัจจัย ÷ Σ(ปัจจัย) × 100`
## คอลัมน์ผลลัพธ์
| คอลัมน์ | ที่มา | คำอธิบาย |
|--------|--------|-------------|
| `target` | อินพุต | ชื่อตัวเลือก |
| `total` | คำนวณ | คะแนนถ่วงน้ำหนัก (0–100) |
| `rank` | คำนวณ | 1 = ดีที่สุด `X` ถ้าถูกบล็อก |
| `block` | อินพุต | ตัวกรองบังคับ ถ้าไม่ว่างแปลว่าไม่ผ่าน ถูกดันลงล่าง rank=X |
| `reason` | อินพุต/เอาต์พุต | ไม่บังคับ: บันทึกของ AI เรื่องความละเอียดอ่อนของคะแนน |
| `<มิติ> (X%)` | คำนวณ | คะแนนตามมิติ หัวตารางแสดงน้ำหนักเป็นเปอร์เซ็นต์ |
| `evidence` | อินพุต | ข้อเท็จจริงที่รองรับคะแนนแต่ละรายการ |
## ระดับคะแนน
- 9–10 — ดีเยี่ยม — ผ่านตามเกณฑ์ทุกข้อ
- 7–8 — ดี — ผ่านตามเกณฑ์ มีช่องว่างเล็กน้อย
- 5–6 — พอใช้ — ทิศทางถูก แต่พลาดในจุดที่สังเกตได้
- 3–4 — อ่อน — มีช่องว่างสำคัญ
- 1–2 — ไม่ผ่าน — แทบไม่ได้พิจารณา
- 0 — ไม่เกี่ยว — ไม่มี
## กฎ
1. **ยึดหลักฐาน** — คะแนนทุกรายการ **ต้อง** มีหลักฐาน ใช้ข้อเท็จจริง ไม่ใช่ความรู้สึก
2. **ใช้ช่วงเต็ม** — 5 คือจุดกึ่งกลาง ไม่ใช่ค่าเริ่มต้น 0 และ 10 พบได้น้อยแต่เป็นไปได้
3. **ปัจจัยคือตัวขยายเชิงสัดส่วน** — ปัจจัย 2 = มีอิทธิพล 2 เท่าของปัจจัย 1 ปรับเป็นสเกลร่วมอัตโนมัติ
4. **เป้าหมายต้องเฉพาะและไม่ว่าง** — คอลัมน์ที่ 1 ของทุกแถวต้องมีชื่อเป้าหมาย ห้ามซ้ำ ห้ามว่าง
5. **agent อ่าน รายงาน และตัดสินใจ** — หลังคำนวณ ให้อธิบายผลลัพธ์ ให้คะแนนใหม่หรือปรับน้ำหนักตามความจำเป็น
