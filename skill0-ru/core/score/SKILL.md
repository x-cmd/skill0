# Score
"Don't guess. Score."
Взвешенный фреймворк оценивания по измерениям для ИИ-агентов.
## Как использовать
**Сначала понять, потом оценивать.** Задай достаточно вопросов, прежде чем определять измерения. Неверные измерения → неверные оценки, какова бы ни была точность.
**Сначала черновик, потом итерации.** Когда потребности не до конца ясны, сделай стандарт по лучшему разумению, оцени и покажи результат. Пользователи реагируют на конкретные ранжирования — «этот factor должен быть выше», «ты упустил X». Это и есть сигнал. Уточни и переоцени. Одна итерация лучше десяти раундов угадывания.
**Агент — аналитик.** После compute прочитай TSV. Объясни, почему X обошёл Y. Выдели неожиданности. Предложи корректировки. Ранжирование начинает разговор, а не завершает его.
## Основной поток
```
① Понять потребности  → ② Определить score.yml  → ③ Оценить score.tsv  → ④ x score compute  → ⑤ Отчёт и итерации
```
Выход: `target, total, rank, block, reason, <dim> (X%), evidence`. Total 0–100, сортировка по убыванию. rank=1 — лучший.
## Пример — помогаем пользователю выбрать рекламный слоган
1. Обсуждаем с пользователем измерения и критерии оценки. Пишем `slogan.score.yml`.
2. ИИ оценивает каждый слоган по измерениям (0–10, с обоснованием) → `slogan.score.tsv`. Total и rank оставляем пустыми.
3. `x score compute slogan.score.yml slogan.score.tsv` → заполняет total + rank.
4. Читаем результаты, обсуждаем с пользователем. Корректируем оценки или добавляем кандидатов, повторяем.
5. Или: `x score iter -f slogan.score.yml slogan.score.tsv "<feedback>"`
Больше примеров: [EXAMPLE.md](EXAMPLE.md).
## Модель из двух файлов
- `*.score.yml` — переиспользуемый стандарт: измерения, факторы, описания
- `**.score.tsv` — цели + оценки + обоснования; колонка 1 = имя цели
`x score compute <yml> <tsv>` эквивалентен `python compute.py`.
## Сценарии применения
1. **Даёт агентам рабочий процесс принятия решений.** score.yml привязывает агента к структурированному процессу — агент следует стандарту, а не настроению последнего сообщения.
2. **Решения принимаются по правилам.** Измерения × факторы × обоснования → взвешенный итог → ранг. Каждая оценка привязана к фактам. Рассуждение прозрачно.
3. **Настраивается под разные потребности.** Меняй измерения, подкручивай факторы, добавляй жёсткие фильтры (колонка `block`). Один шаблон — разные пользователи.
4. **Развивается по мере прояснения потребностей.** Черновик → оценка → обратная связь → уточнение → резче.
5. **Стандартный файл + архив результатов для любого навыка.** score.yml = стандарт решения. score.tsv = запись решения. Оба можно архивировать, ревьюить и распространять.

## Формула
```
total = Σ(factor × score) ÷ Σ(factor) × 10   →   0–100
```
- **factor** — целое 1–10. Базовая = 2. 1=незначительный, 4=2×, 6=3×, 8=4×, 10=5×. Нормируется автоматически.
- **score** — 0–10 по каждому измерению, привязан к обоснованию.
- **total** — взвешенный итог 0–100.
В заголовках измерений показан вес %: `factor ÷ Σ(factor) × 100`.
## Колонки выхода
| Колонка | Источник | Описание |
|--------|--------|-------------|
| `target` | ввод | Имя кандидата |
| `total` | вычисляется | Взвешенная оценка (0–100) |
| `rank` | вычисляется | 1 = лучший. `X`, если заблокирован |
| `block` | ввод | Жёсткий фильтр — непусто = дисквалификация, отправляется вниз, rank=X |
| `reason` | ввод/вывод | Необязательно: заметки ИИ о нюансах оценки |
| `<dim> (X%)` | вычисляется | Оценки по измерениям, в заголовке вес % |
| `evidence` | ввод | Факты за каждым баллом |
## Шкала
- 9–10 — Отлично — полностью удовлетворяет критериям
- 7–8 — Хорошо — удовлетворяет критериям, небольшой пробел
- 5–6 — Приемлемо — направление верное, заметный пробел
- 3–4 — Слабо — значительный пробел
- 1–2 — Провал — едва затронуто
- 0 — Н/П — неприменимо
## Правила
1. **Привязка к обоснованию** — у каждой оценки ДОЛЖНО быть обоснование. Факты, а не ощущения.
2. **Используй весь диапазон** — 5 это середина, а не значение по умолчанию. 0 и 10 редки, но возможны.
3. **Факторы — относительные усилители** — factor 2 = двукратное влияние factor 1. Нормируется автоматически.
4. **Цели уникальны и непусты** — в колонке 1 каждой строки должно быть имя цели. Без дублей и пустых значений.
5. **Агент читает, отчитывается, решает** — после compute объясни результаты. При необходимости переоцени или перевзвесь.
