# repo

## Зачем

Все клоны сходятся в `~/.x-repo/<provider>/<owner>/<name>`. Один и тот же путь для любого агента, человека, CI — его можно монтировать в контейнеры или песочницы агентов, чтобы они делились репозиторием без повторного клонирования. Один корень для резервного копирования; обнаруживается через `x repo ls`. Раскладка повторяет пути GitHub, поэтому `../<sibling>` из любого worktree резолвится в дефолтный worktree этого соседа — конфиги и скрипты со ссылками на соседей работают единообразно во всех wt и у всех агентов.

## Раскладка путей

- bare: `~/.x-repo/.bare/<provider>/<owner>/<name>.git`
- дефолтный wt: `~/.x-repo/<provider>/<owner>/<name>`
- именованный wt: `~/.x-repo/<provider>/<owner>/<name>@<wtname>`

`@<wtname>` — wtname это любой идентификатор рабочего пространства: имя агента/воркера, имя ветки, тег, короткий SHA, id задачи, произвольная строка. `/` в wtname кодируется как `~`.

По умолчанию репозитории bare со связанными worktree — bare лежит в `.bare/`, в отдельном каталоге от worktree, поэтому `rm -rf` одного wt его не достанет. Обычный `git clone` тоже допускается (`x repo ls/which/update` его видят), но без геометрической защиты. В этом случае будь осторожен: не делай `rm -rf`, предпочитай `git worktree remove` и избегай эвристик очистки, нацеленных на `.git/`. Работа, потерянная таким образом посреди задачи, больше не будет согласована с исходным репозиторием.

## Commands

```bash
x repo <id>                      # cd в дефолтный wt (сам клонирует, если нет)
x repo wt <id> <wtname>          # подключиться к существующей ветке или создать новую от HEAD
x repo wt ls <id>                # список wt
x repo wt rm <id> <wtname>       # корректное удаление (используй это, а не rm -rf)
x repo update <id>               # обновить дефолтный wt после изменений в upstream
x repo ls [--raw|--tsv]          # обнаружить, что склонировано
x repo which <id>[@<wtname>]     # разрезолвить id в абсолютный путь
```

## Не делай

- `rm -rf` именованного worktree. Это оставляет устаревшие записи в реестре `worktrees/` у bare. Используй `x repo wt rm`. Если всё же пришлось, после этого выполни `git -C <bare> worktree prune`.
